# 01 — Streamlit UI and the two event payloads

## 1. UI initialization

`st.set_page_config(...)` configures page title, icon and layout. `st.file_uploader(type=["pdf"], accept_multiple_files=False)` creates the upload widget. Streamlit generally reruns the script on widget interaction. `st.form` groups input controls so the query is submitted together with `top_k`.

## 2. Save the file

`save_uploaded_pdf(file)` creates `uploads/`, writes the uploaded bytes, and returns a `pathlib.Path` instance. **The return value is a file path, not PDF text.** `file.name` is the original name; `path.resolve()` makes the path absolute.

## 3. Emit the ingestion event

```python
inngest.Event(name="rag/ingest_pdf", data={
    "pdf_path": str(pdf_path.resolve()),
    "source_id": pdf_path.name,
})
```

The `data` mapping is the **event payload**. It does not contain chunks or vectors. The same-named trigger in `main.py` selects the ingestion workflow. `source_id` here is a filename defined by our code, not a unique identifier generated by Inngest.

## 4. Emit the query event

```python
inngest.Event(name="rag/query_pdf_ai", data={"question": question, "top_k": top_k})
```

The query event is different from ingestion. `ctx.event.data["question"]` retrieves the question inside the invoked workflow; `ctx.event.data.get("top_k", 5)` supplies 5 when absent. Inngest itself supplies `ctx` to the function.

## 5. Poll for the result

`send_rag_query_event(...)` returns `result[0]` (the event ID in the examined SDK usage). `fetch_runs(event_id)` makes a GET request to `INNGEST_API_BASE` (default `http://127.0.0.1:8288/v1`). `wait_for_run_output` retries every 0.5 seconds until a terminal status or 120-second timeout, then Streamlit displays `answer` and `sources`.

**Important:** `client.send(...)` confirming the event was sent is not the same as confirming ingestion completed. The upload interface reports triggered ingestion, not successful indexing.

## Things to improve

- Prevent duplicate uploads on Streamlit reruns.
- Validate filename, extension, MIME/content and size.
- Report actual workflow completion status.
- Set explicit HTTP timeouts and handle network failures.
- For distributed deployment, replace local file paths with durable shared/object storage.
